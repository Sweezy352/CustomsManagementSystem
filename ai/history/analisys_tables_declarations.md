Давайте разберем таблицы `Declaration` и `DeclarationProduct` на простом примере.

Представьте, что вы отправляете посылку:
*   **`Declaration`** — это сама коробка, на которой написан ваш адрес, адрес получателя и тип отправления.
*   **`DeclarationProduct`** — это список вещей, которые лежат *внутри* этой коробки.

---

### 1. Таблица `Declaration` (Декларация)

Это "шапка" или "обложка" всего документа. Она содержит общую информацию о таможенной операции, но не о конкретных товарах.

**Ее главная задача — ответить на вопросы:**
*   **Кто** подает декларацию? (ID компании или физ. лица)
*   **Что это за операция?** (Импорт или экспорт)
*   **На каком этапе она находится?** (Черновик, подана, на проверке и т.д.)

| Поле | Описание |
| :--- | :--- |
| `id` | Уникальный номер декларации. |
| `company_id` | ID компании, которая подает декларацию. |
| `individual_id`| ID физ. лица (если подает не компания). |
| `type` | Тип операции: `IMPORT` или `EXPORT`. |
| `status` | Текущий статус: `DRAFT`, `SUBMITTED`, `IN_REVIEW` и т.д. |
| `created_at` | Дата создания. |
| `submitted_at` | Дата подачи инспектору. |
| `reviewed_by` | ID инспектора, который проверяет декларацию. |

---

### 2. Таблица `DeclarationProduct` (Товары в декларации)

Это "содержимое" или "список товаров" внутри одной декларации. Каждая строка в этой таблице — это отдельный товар в поставке.

**Ее главная задача — ответить на вопросы:**
*   **Что именно** ввозится/вывозится? (Название, код ТН ВЭД)
*   **Сколько** этого товара? (Количество, вес)
*   **Какова его стоимость** и происхождение? (Цена, страна)

Ключевое поле здесь — **`declaration_id`**. Это **внешний ключ**, который связывает каждый товар с его "шапкой" (декларацией) из первой таблицы.

| Поле | Описание |
| :--- | :--- |
| `id` | Уникальный номер записи о товаре. |
| `declaration_id`| **Связь с таблицей `Declaration`**. Указывает, к какой декларации относится этот товар. |
| `name` | Коммерческое название товара (например, "Смартфон Model X"). |
| `tnved_code` | Таможенный код товара. **Ключевое поле для расчета пошлин.** |
| `quantity` | Количество единиц товара. |
| `weight` | Общий вес товара. |
| `price_per_unit` | Цена за одну единицу товара. |
| `country_of_origin`| Страна, где товар был произведен. |

---

### Пример из жизни

Допустим, компания "Bishkek Style" (ID = 55) импортирует из Китая партию смартфонов и чехлов к ним.

**1. Сначала создается одна запись в таблице `Declaration`:**

Она говорит: "Компания 55 импортирует товары, декларация подана на проверку".

| id | company_id | individual_id | type | status | submitted_at |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **101** | 55 | NULL | `IMPORT` | `SUBMITTED` | 2023-10-27 10:00:00 |

**2. Затем создаются две записи в `DeclarationProduct`**, потому что в поставке два разных товара.

Обе записи ссылаются на `declaration_id = 101`, показывая, что они лежат в "одной коробке".

| id | declaration_id | name | tnved_code | quantity | price_per_unit | country_of_origin |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 2001 | **101** | Смартфон Model X | 8517120000 | 100 | 250.00 | CN |
| 2002 | **101** | Силиконовый чехол | 3926909709 | 200 | 2.50 | CN |


Таким образом, система понимает, что **декларация №101** от компании "Bishkek Style" содержит 100 смартфонов и 200 чехлов. Инспектор откроет эту декларацию и увидит оба товара для проверки и расчета пошлин.
